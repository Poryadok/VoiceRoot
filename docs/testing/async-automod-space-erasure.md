6. RACES, RESTART AND RESTORE
Insert versus Space freeze: retain existing Chat/Space lock ordering, then account/source lock. Either insertion commits with one core and its temporary coverage bridge before the exact freeze capture, or it is denied by the freeze; there is no orphan message or uncovered commit. Freeze deletion of bridges does not mutate any core or increment its source sequence.

Dispatch versus bridge erasure: every v2 worker serializes only core fields. A worker which read core bytes before erasure may complete that same account-purpose delivery afterward. This is permitted data flow, not a late reintroduction of erased origin identifiers. No distributed cancellation claim is needed. A worker which read v1 bytes is unsupported at activation; old-version workers must be stopped/fenced before conversion or deployment.

Source-age expiry versus delivery: existing core/hash/age checks select one terminal ordered outcome under local account serialization; late retries are no-ops. Bridge deletion is an independent local cleanup and cannot cause an early expiry or a false ACK. Account terminal purge may delete the core, source mapping and bridge regardless of unacknowledged work; the terminal subject fence then wins over all retries.

Crash around freeze/purge: bridge deletion and its local fence/cleanup acknowledgment commit together. Crash before commit repeats; crash after commit/response loss returns the saved receipt without recreating links or resending evidence as a new record. Origin-free core delivery can continue independently after recovery only when c13 gates permit it.

Replay from an old core remains subject to the existing source epoch/cursor and account terminal fences. A live v2 core behind an already applied cursor is retired/duplicate, not new spam.
