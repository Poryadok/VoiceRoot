# Friends & Contacts — друзья и контакты

## Два уровня отношений

| Уровень | Как возникает                                     | Что видит                                                                     |
|---------|---------------------------------------------------|-------------------------------------------------------------------------------|
| Контакт | Автоматически из телефонной книги или через поиск | Ник профиля; телефон — только если нашёл по нему                              |
| Друг    | Двустороннее подтверждение (как ВКонтакте)        | Больше данных: телефон даже без знания номера, приватные данные по настройкам |

Контакт может отправить запрос в друзья → пользователь принимает → контакт становится другом.

## Добавление в друзья

Способы отправить запрос:
- По @username
- По номеру телефона
- По QR-коду
- Из общего спейса / чата
- Из истории ММ
- Кнопка "добавить" в профиле

Поиск по строке для заявки в друзья / открытия профиля — **User Service**, RPC `SearchProfiles` (данные из `user_db`; не Search Service). Полнотекст и глобальный поиск — **Search Service** ([search.md](search.md)), см. [user-service.md](../microservices/user-service.md).

Отклонённый запрос **виден** отправителю.

## Контакты из телефонной книги

- Пользователи из телефонной книги, которые есть в Voice, автоматически становятся контактами
- Отдельного списка нет — контакты доступны через поиск
- Можно запретить контактам писать в DM (настройка приватности)

## Незнакомец пишет

Если пользователь, которого **нет в друзьях и контактах**, пишет в DM и privacy `allow_dm` разрешает:

| Сторона | `inbox_bucket` | UI |
|---------|----------------|-----|
| **Отправитель** | `main` | Чат в основном списке |
| **Получатель** | `requests` | Virtual folder «Запросы»; `ChatListItem.is_stranger=true` |

- Оповещение: тип **`message_request`** — label «Незнакомец» / «Message request» ([notifications.md](notifications.md))
- **Accept** (`AcceptDMRequest`) → оба в `main`; переписка в обычном inbox
- **Decline** (`DeclineDMRequest`) → у получателя `declined`; чат скрыт из requests/main
- **Re-contact:** новое сообщение от того же отправителя после decline → у получателя снова `requests`

**Friends и contacts bypass:** если отправитель — друг или контакт из телефонной книги → оба участника сразу `main`, без папки запросов.

Полный state machine — [text-chat.md](text-chat.md) § «Запросы сообщений», [GLOSSARY.md](../GLOSSARY.md) § «Запросы сообщений».

## Списки — Steam-модель

- Друзья
- **Избранные** (люди — favourites)
- Заблокированные (блокировка только в ММ — отдельная; блокировка в мессенджере — эта)

### Избранные друзья ≠ Quick Access

| | **Friends → Favourites** | **Rail → Quick Access** |
|--|--------------------------|-------------------------|
| **Что** | Люди (профили / друзья) | Чаты активного профиля |
| **Где** | Social panel | Desktop rail (до 15 чатов) |
| **Зачем** | Быстрый доступ к людям | Быстрый переход в переписку |
| **Док** | этот файл | [navigation.md](navigation.md), [GLOSSARY.md](../GLOSSARY.md) |

Третья сущность — **pin чата в папке** (сортировка внутри folder filter), не путать с обоими выше.

## Что даёт статус друга

- Быстрый поиск контакта
- Видно онлайн-статус (по настройкам приватности)
- Доступ к бо́льшему объёму данных профиля
- Настройки приватности (сторис, телефон и др.) можно ограничить только для друзей
