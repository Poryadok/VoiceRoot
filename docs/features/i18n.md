# Локализация (i18n) — интернационализация

## Языки

| Версия | Языки                      |
|--------|----------------------------|
| v1     | English (en), Русский (ru) |
| Позже  | По мере спроса — любые     |

Новый язык добавляется без изменений кода: только новый ARB-файл с переводами.

## Клиент (Flutter)

**Стек:** `flutter_localizations` + `intl` + ARB-файлы.

- Строки хранятся в `lib/l10n/app_en.arb`, `app_ru.arb` и т.д.
- Плюрализация через ICU MessageFormat — покрывает сложные правила русского языка (1 сообщение / 2 сообщения / 5 сообщений)
- Форматирование дат и чисел через `intl` — locale-aware автоматически
- Язык: берётся из системных настроек; ручная смена в настройках приложения
- Язык хранится в профиле пользователя и синхронизируется между устройствами

### Приоритет языка и сохранение

1. Ручной выбор English / Русский сохраняется через `UpdateProfile` в
   `profile.locale` (`en` / `ru`). Клиент применяет его после успешного ответа
   с тем же профилем и языком; ошибка сохраняет прежний язык и позволяет retry.
2. Без временного выбора клиент использует язык текущего активного профиля.
   При переключении профиля, смене сессии или перезагрузке язык снова берётся
   из профиля. Изменение, сохранённое на другом устройстве, применяется при
   следующей загрузке профиля; отдельный realtime-протокол синхронизации не
   требуется.
3. `System default` временно использует язык ОС в текущем контексте
   профиля/сессии. Этот выбор не сбрасывает серверный `profile.locale` и не
   сохраняется между перезагрузками или сменой сессии/профиля: серверное поле
   допускает только `en` / `ru`, а не значение `system`.
4. Пока профиль недоступен, его язык не поддерживается или активного профиля
   нет, применяется системный язык. Если ОС не предлагает поддерживаемый язык,
   используется стандартный fallback Flutter на English.

Ответ сохранения, пришедший после переключения профиля или смены сессии, не
меняет язык нового контекста. Локальный выбор одного профиля не становится
предпочтением другого.

```
lib/
  l10n/
    app_en.arb
    app_ru.arb
    app_de.arb   ← пример будущего добавления
```

## Бэкенд

- Системные сообщения (уведомления, email) — генерируются на языке пользователя; язык берётся из профиля
- API возвращает данные as-is, без перевода (контент пользователей не переводится сервером)
- Сообщения об ошибках от API — на английском (локализуются на клиенте по error code)

## Full-text Search

Канонический выбор движка зафиксирован в `search.md` и `MICROSERVICES.md`.

**Решение для v1:**
- PostgreSQL `tsvector` + `GIN` (simple-конфигурация без стемминга как базовый безопасный режим для mixed-language контента)
- `pg_trgm`/`ILIKE` допускаются как точечное fallback-решение для отдельных полей, но не как основной message index

**При масштабировании:**
- Если нужен языковой стемминг — добавлять language-aware индексацию на этапе пайплайна
- Основной путь роста: переход на Meilisearch/Elasticsearch по порогам из `search.md`

## RTL (Right-to-Left)

Арабский, иврит и другие RTL-языки требуют отдельного архитектурного решения во Flutter:
- Все отступы через `EdgeInsetsDirectional` вместо `EdgeInsets`
- Layout через `start`/`end` вместо `left`/`right`
- Ряд иконок/элементов нужно зеркалить

**Решение: RTL не поддерживается в v1.** При добавлении RTL-языка — отдельный технический тред. Закладывать с самого начала не нужно, но не использовать хардкод `left`/`right` там, где это легко избежать.

## Что НЕ входит в scope

- Machine translation сообщений (как в Telegram Premium) — отложено
- Локализация пользовательского контента (названия спейсов, чатов, голосовых комнат) — остаётся как есть
- Региональные версии приложения с разным функционалом — нет
