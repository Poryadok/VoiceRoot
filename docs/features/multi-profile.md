# Multi-Profile — множественные профили

## Концепция

Один аккаунт может иметь несколько независимых профилей — отдельных "цифровых личностей" (личный, рабочий, игровой и т.д.). Профили не видны друг другу: собеседник знает только тот профиль, через который с ним общаются.

## Количество профилей

- Бесплатно: до 2 профилей
- По подписке: до 5 профилей

## Создание и настройка

- Создаётся из настроек аккаунта: ник, аватар
- Можно привязать дополнительный номер телефона (не основной)
- Один профиль назначается основным — именно он показывается при поиске по номеру
- Значок верификации (✅ / ®) привязан к конкретному профилю, не к аккаунту
- При создании можно выбрать пресет (Личный / Игровой / Рабочий) с предустановленными настройками — см. [privacy.md](privacy.md)

## Переключение

- Мгновенное, без перезагрузки приложения
- **Десктоп:** avatar в rail **ProfileStack** → контекстное меню §1.1a ([screen-controls.md](../design/screen-controls.md) §1.1 #6, §1.1a; [navigation.md](navigation.md) § Rail #5) — switch, create profile, presence, Archive; отдельного session-bar combobox нет
- **Мобайл:** tap avatar → то же меню §1.1a; **swipe** по avatar для быстрого switch ([screen-controls.md](../design/screen-controls.md) §1.1 #6, [H vs V summary](../design/screen-controls.md#h-vs-v-layout-differences-summary))
- Каждый профиль имеет свою цветовую тему для визуальной индикации

## Контакты и друзья

- Контакты и друзья принадлежат профилю, не аккаунту
- Один пользователь может быть другом разных профилей одного аккаунта (собеседник не знает, что это один человек)
- При поиске по телефону показывается основной профиль; после добавления можно перевести контакт в нужный профиль
- **Блокировка** распространяется на весь аккаунт — обойти через другой профиль нельзя

## Спейсы

- Членство в спейсах принадлежит профилю
- Один аккаунт может состоять в одном спейсе разными профилями
- Переключение профиля — глобальное: нельзя сменить профиль "внутри" спейса

### Поведение при переключении профиля в спейсе

При переключении профиля во время нахождения в спейсе:
- Если Профиль B тоже является участником этого спейса — приложение тихо переключает контекст, пользователь остаётся в том же спейсе (уже от имени нового профиля)
- Если Профиль B не является участником — редирект на главный экран
- При переключении во время активного войс-чата — войс **не разрывается** (подробнее см. раздел «Войс при смене профиля»); текстовый контекст переключается на Профиль B

## Статусы и уведомления

- У каждого профиля свой статус и свои настройки уведомлений
- Уведомления приходят по настройкам каждого профиля независимо от того, какой активен
- Если на неактивном профиле стоит DND — его уведомления не показываются; если DND нет — приходят

## Матчмейкинг

- ММ запускается от активного профиля
- Смена профиля во время поиска выводит из пати (поиск сбрасывается)
- Игровые данные (ранг, предпочтения) хранятся в профиле, в котором были заданы

## Войс при смене профиля

Войс-соединение принадлежит конкретному профилю, в котором оно было начато. Правила:

- **Смена профиля не разрывает активный войс-чат.** Пользователь остаётся в войс-сессии под исходным профилем, пока явно не выйдет из неё.
- **В текстовых чатах можно свободно переключаться** между профилями, не выходя из войса.
- **Зайти в другой войс-чат** под текущим профилем нельзя, пока активна войс-сессия другого профиля — сначала нужно выйти из неё. При попытке перейти в другой войс-чат показывается диалог: *"Ты сейчас в войс-чате (Профиль A). Выйти из него и войти сюда?"*. При подтверждении — старая сессия завершается, новая открывается под активным профилем.
- **Два войс-чата одновременно** — невозможно, даже если это разные профили одного аккаунта.

## Монетизация

- Подписка и платежи привязаны к аккаунту
- Красивый ник (@username без #1234) — один в рамках подписки на аккаунт
- Дополнительные красивые ники для других профилей — докупаются отдельно
- Бонусы подписки (например, увеличенный размер файлов) применяются ко всем профилям аккаунта

### Downgrade и renewal (accepted A7 target)

Во время cancel-at-period-end или grace экран позволяет заранее выбрать второй
профиль; основной profile ID резервирует первый слот, а при наличии eligible
secondary picker требует exact pair с owned, non-deleted профилем без другой
disabled/frozen причины. До `inactive` никто не замораживается.
Выбор привязан к стабильному `downgrade_cycle_id`, который переживает возможный
failed-payment grace и непосредственный переход в `inactive`, но очищается при
recovery/resume/renewal или новой покупке/`STARTED`. При
`inactive` User применяет сохранённую пару даже без открытого клиента; при
отсутствии/невалидности выбора fallback — основной и самый ранний eligible из
остальных. Если eligible secondary нет, резервируется только основной и чужие
disabled/frozen причины не снимаются. Все остальные non-deleted профили получают
отдельный subscription-freeze overlay, даже если уже disabled по иной причине,
чтобы последующее снятие этой причины не превысило free-limit. Все excess-профили сохраняются, но помечаются именно
как subscription-frozen. Grace не замораживает профили.

Выбор привязан к downgrade cycle: повтор безопасен, а запоздалый выбор после
renewal не может снова заморозить данные. При возврате в `active` User
размораживает только subscription-frozen профили; удалённые или отключённые по
другой причине не восстанавливаются. Детальный межсервисный контракт и RED
сценарии —
[subscription-lifecycle-convergence-exec-plan.md](../testing/subscription-lifecycle-convergence-exec-plan.md).

## Защита от злоупотреблений

- Ограничение на частоту создания/удаления профилей (антиспам)
- При удалении профиля данные архивируются на бэкенде; пользователь этого не видит
