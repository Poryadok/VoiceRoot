# Auth & Contacts — регистрация и контакты

## Способы регистрации

| Способ         | Статус       | Примечание |
|----------------|--------------|------------|
| Email          | Alpha default | Основной способ для Web/Windows invite alpha; регистрация требует server-signed invite |
| Номер телефона | Post-alpha | Не показывается, пока не выбраны SMS provider и anti-abuse flow |

Подтверждённый email-аккаунт — обычный `regular`-аккаунт без отдельных ограничений
или бейджа «без телефона». Телефон может позднее использоваться для discovery и
дополнительного trust signal, но его отсутствие само по себе не ограничивает DM.

## Гостевая учётка

- При открытии веб-версии без входа автоматически создаётся временный аккаунт
- Сессия (access/refresh) хранится в **локальных prefs** (`SharedPreferences` / `localStorage` на web), не в HTTP cookies; переживает F5 и пересборку фронта, пока не выполнен logout, не отозван refresh и не снесены volume БД (`docker compose down -v`)
- Гость может делать всё, что разрешено гостям в конкретном чате (настраивается на уровне чата/спейса)
- Гость **не может**:
  - Инициировать разговор (DM, войс-звонок)
  - Самостоятельно вступать в чаты и спейсы — только по инвайту
  - Добавлять в друзья
- При регистрации история гостя **переносится** на новый аккаунт
- У каждого спейса и чата есть настройка: разрешать ли вход гостям

### Первый вход — выбор никнейма

При первом создании гостевого аккаунта (кнопка «Продолжить как гость» или auto-register на вебе) показывается экран выбора никнейма. Без никнейма в основной интерфейс не пускать.

На этом первом входе **не** показывать напоминание «сохрани аккаунт / ник» — пользователь только что задал имя.

### Напоминание сохранить аккаунт (повторные входы)

Начиная со **второго** входа гостя (новая сессия на том же или другом устройстве, пока аккаунт остаётся `guest`) показывать ненавязчивое напоминание зарегистрировать аккаунт, чтобы не потерять доступ и данные.

| Условие | Поведение |
|---------|-----------|
| Первый вход (сразу после создания guest + nickname screen) | Напоминание **не** показывать |
| Каждый последующий вход | Показывать напоминание |
| Частота | Не чаще **одного раза в сутки** (локальный или серверный timestamp последнего показа) |

CTA в напоминании ведёт в flow регистрации гостевого аккаунта (см. ниже), не в общие настройки.

### Регистрация гостевого аккаунта (convert-guest)

Когда гость решает оформить постоянный аккаунт, открывается **отдельное модальное окно** (dialog / bottom sheet), а не переход в раздел настроек.

Поля формы (на текущий момент):

| Поле | Обязательно |
|------|-------------|
| Email | Да |
| Пароль | Да |

Отправка — `POST /api/v1/auth/convert-guest` (тот же `account_id` / `profile_id`, история сохраняется). Поле `password` — **новый пароль**, который пользователь задаёт в форме; transport-пароль после успешной конвертации больше не нужен.

После отправки формы создаётся pending email identity и отправляется verification.
Сессия, история и те же `account_id` / `profile_id` сохраняются, но до подтверждения
email действуют guest-level ограничения. После успешной verification переход в
`regular` выполняется атомарно, guest reminders прекращаются и публикуется
`user.guest_converted`. Неподтверждённый email никогда не считается verified identity.

### Видимость для владельца профиля (настройки приватности)

В настройках приватности профиля — "Гостевые аккаунты" является отдельной опцией аудитории. Позволяет отдельно регулировать, что видят гости, независимо от настроек для зарегистрированных пользователей.

Применяется к:
- Онлайн-статус
- Статус «в игре»
- Рейтинг ММ
- Стори

Действия (DM, звонок, приглашение в друзья) **инициировать** гостям недоступны вне зависимости от настроек — настройка этих полей не применяется к гостям как к инициаторам. Зарегистрированный пользователь **может позвонить гостю**, если гость уже принимает DM (gaming default: `allow_dm = everyone_with_guests`; для гостевого callee `allow_calls` при enforcement трактуется как DM-аудитория).

## Идентификатор пользователя

| Тип                       | Формат                                                  | Условие                                                                                       |
|---------------------------|---------------------------------------------------------|-----------------------------------------------------------------------------------------------|
| Стандартный               | `@username#1234`                                        | Бесплатно                                                                                     |
| Премиум                   | `@username`                                             | Подписка                                                                                      |
| Верифицированная личность | `✅username` (в UI — системная иконка, не символ в нике) | Доказательство через OAuth: Twitch Partner / YouTube YPP — [verification.md](verification.md) |
| Компания / юрлицо         | `®companyname` (в UI — системная иконка)                | Владение доменом: TXT в DNS + ручной fallback — [verification.md](verification.md)            |

Дискриминатор `#1234` у стандартных аккаунтов назначается случайно и не выбирается
пользователем. В текущем scope меняется только `@username` по правилам тарифа;
кастомизация discriminator не входит в продукт.

## Контакты по телефону

- Механика как в Telegram / WhatsApp: пользователь разрешает доступ к телефонной книге, приложение показывает кто из контактов уже в Voice
- Работает в обе стороны: если пользователь ввёл номер и разрешил поиск — его можно найти

## Сессии и безопасность

- **Токены**: JWT access token (15 мин) + opaque refresh token (30 дней) в DB
- **Таблица**: `refresh_tokens(id, account_id, token_hash, device_info, expires_at, created_at, revoked_at)`  
  (`user_id` в JWT claim историческое имя, значение = `account_id`)
- **Инвалидация**: смена пароля → удалить все refresh tokens; logout → удалить один
- **Досрочный отзыв**: Redis blacklist для access token до истечения TTL
- **Сессии**: неограниченно одновременно → страница "Активные устройства" в настройках
- **Восстановление пароля**: через email (ссылка/код на почту)
- **Rate limiting авторизации**: 5 попыток / 15 мин с одного IP → блок 15 мин (экспоненциально); OTP: 3 попытки / 10 мин, новый код не чаще раза в минуту; реализация — Redis sliding window

## Гостевой аккаунт — жизненный цикл

- Истекает через 30 дней после последнего онлайна
- Ограничений по количеству чатов/сообщений нет

## Удаление аккаунта / GDPR

- Удаление требует повторного подтверждения паролем и 2FA, если он включён, плюс
  явного destructive confirmation в UI.
- Сразу после подтверждения аккаунт деактивируется, все sessions/refresh tokens
  отзываются, профиль скрывается, а на email отправляется одноразовый restore flow.
- **Recovery window — 30 дней**. В течение него владелец может восстановить аккаунт;
  после истечения восстановление невозможно.
- После 30 дней PII и credentials удаляются либо необратимо псевдонимизируются:
  email, phone, password/TOTP/recovery secrets, sessions, profile name/bio/media и
  linked identities больше не позволяют восстановить личность.
- Сообщения остаются в истории с системным tombstone author «Пользователь удалён»;
  стабильный внутренний tombstone ID не раскрывается клиенту и не позволяет найти
  удалённый профиль.
- Минимальные anti-abuse/legal records хранятся отдельно от пользовательского
  профиля по утверждённой для production retention policy; они не используются для
  восстановления аккаунта или обычного product lookup.

### Что видят другие после удаления аккаунта

- **История чата**: на устройствах, где DM уже загружен, сообщения удалённого пользователя остаются. `Messaging.GetMessages` для этого выбранного известного DM возвращает response-level `dm_peer_state=DELETED`, не создавая строку `Message`, не меняя историю или cursor и не раскрывая ID удалённого account/profile. Клиент показывает в конце ровно один локальный, неперсистентный и локализованный marker «Пользователь удалён»; отправлять новые сообщения в этот DM нельзя.
- **Live-ускорение**: `chat.dm_peer_deleted` доставляется только surviving `recipient_profile_id` с `chat_id`; это ускоряет marker на уже открытом экране, но не заменяет `GetMessages` и не передаёт deleted identity.
- **Новые устройства**: успешный свежий `Chat.ListChats` snapshot не содержит DM с удалённым пользователем; без уже загруженной истории клиент не создаёт marker.
- **Профиль по ссылке**: страница "Аккаунт удалён" (без данных).
- **В списках участников спейса**: пользователь не отображается после удаления.

Этот immediate DM-contract не создаёт persistent tombstone и не меняет recovery window. Полное стирание/псевдонимизация через 30 дней и UX восстановления остаются scope A4.

## Email verification state

- Новая email-регистрация и `convert-guest` получают restricted pending session:
  доступны verification/resend/logout и уже разрешённые guest flows.
- Инициировать DM/звонок, добавлять друзей и самостоятельно вступать в Space до
  verification нельзя.
- Повторная отправка verification не создаёт новый аккаунт и не меняет identity IDs.
- Только подтверждение email открывает regular-возможности и завершает conversion.
