# Deep Links / Sharing — схема URL

Единая схема ссылок для навигации внутри приложения и шаринга наружу.

## Два формата

| Контекст                | Формат                 | Пример                                          |
|-------------------------|------------------------|-------------------------------------------------|
| Веб / внешние платформы | `https://voice.gg/...` | Открывается в браузере, редиректит в приложение |
| Прямой диплинк          | `voice://...`          | Открывается напрямую в приложении               |

Оба формата ведут на одно и то же. Веб-версия определяет, установлено ли приложение, и редиректит; если нет — открывает веб-клиент.

Ссылки, созданные работающим Web-клиентом, используют его публичный origin.
Для staging это host из `VOICE_WEB_INGRESS_HOST` (например,
`app.comrade.click`), на котором открыт клиент; parser принимает этот же текущий
origin. Нативный клиент без web-origin использует canonical `voice.gg`.

## Схема URL

### Спейс

```
voice://s/{spaceId}
https://voice.gg/s/{spaceId}
```
Открывает спейс: дефолтный **текстовый чат** (канал или группа — политика клиента, например первый доступный) или экран вступления, если пользователь не участник.

### Текстовый чат в спейсе (группа или канал)

```
voice://s/{spaceId}/c/{chatId}
https://voice.gg/s/{spaceId}/c/{chatId}
```

`{chatId}` — UUID строки `chat_db.chats.id` с `type = group` или `type = channel`.

### Голосовая комната в спейсе

```
voice://s/{spaceId}/v/{voiceRoomId}
https://voice.gg/s/{spaceId}/v/{voiceRoomId}
```

`{voiceRoomId}` — UUID строки `space_db.voice_rooms.id`.

### Конкретное сообщение в текстовом чате спейса

`{chatId}` здесь — **`chat_db.chats.id`** потока сообщений (`group` \| `channel`).

```
voice://s/{spaceId}/c/{chatId}/m/{messageId}
https://voice.gg/s/{spaceId}/c/{chatId}/m/{messageId}
```
Открывает чат, скроллит к сообщению и подсвечивает его.

### Текстовый чат вне спейса (группа или канал)

```
voice://ch/{chatId}
https://voice.gg/ch/{chatId}
```

### Сообщение в текстовом чате вне спейса

```
voice://ch/{chatId}/m/{messageId}
https://voice.gg/ch/{chatId}/m/{messageId}
```

### Профиль пользователя

```
voice://u/{username}
https://voice.gg/u/{username}
```
Открывает публичный профиль. Username — уникальный handle (например, `@vanya`).

### Инвайт в спейс

```
voice://invite/{inviteCode}
https://voice.gg/invite/{inviteCode}
```
Открывает экран принятия инвайта. Если уже участник — редиректит в спейс.

### Личный чат (DM)

```
voice://dm/{userId}
https://voice.gg/dm/{userId}
```
Открывает ЛС с пользователем. Если чата нет — создаёт новый (или предлагает создать, если приватность запрещает DM).

## Поведение при переходе

| Состояние                                       | Поведение                                                       |
|-------------------------------------------------|-----------------------------------------------------------------|
| Приложение установлено и пользователь залогинен | Открывает нужный экран                                          |
| Приложение установлено, не залогинен            | Открывает экран входа, после входа — нужный экран               |
| Приложение не установлено                       | Открывает веб-клиент или Store/Market с предложением установить |
| Нет прав доступа к объекту                      | Показывает ошибку "Нет доступа"                                 |
| Объект удалён                                   | Показывает ошибку "Не найдено"                                  |

## Шаринг

Из любого объекта (сообщение, профиль, спейс) доступна кнопка "Поделиться", которая копирует ссылку текущего публичного Web-origin в буфер обмена; для нативного клиента без web-origin используется `https://voice.gg/...`.

## UTM-параметры

Поддерживаем UTM для аналитики источников переходов. Все ссылки из кнопки "Поделиться" генерируются без UTM — пользователь добавляет вручную при желании; внутренние интеграции (онбординг, нотификации) проставляют UTM автоматически.

## Диплинки на профиль

Ссылка на профиль строится по `@username`, не по `userId`. Гостевые аккаунты ссылок не имеют — при регистрации пользователь получает username и ссылка становится доступна.

## Service Ownership

- Edge owner: `API Gateway` (парсинг URL, auth-редиректы, базовая валидация схемы)
- Domain ownership: `Space Service`, `Chat Service`, `Messaging Service`, `User Service`, `Social Service` (валидация доступа к целевому объекту)

## Enforcement path

1. Клиент/веб открывает `voice://...` или `https://voice.gg/...`.
2. `API Gateway` нормализует маршрут и определяет доменный target.
3. Соответствующий доменный сервис проверяет существование ресурса и ACL.
4. Клиент получает либо разрешённый target, либо `404/403` и показывает "Не найдено"/"Нет доступа".
